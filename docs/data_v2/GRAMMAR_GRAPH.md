# Grammar Graph Engine — Step 4

**Module:** `src/irab_tashkeel/grammar_graph/`

The grammar graph engine sits on top of schema_v2 sentences and
produces a unified multi-typed node + multi-typed edge graph that
Step 5 long-range reasoning, Step 8 decoding, and future GNN
architectures can consume.

## Node types

| node_type | source | populated when |
|---|---|---|
| `token` | `Sentence.tokens` | always |
| `construction` | `Sentence.constructions` | after construction-detector pass |
| `clause` | `Sentence.clauses` | after Step 5 clause-detector lands |
| `phrase` | `Sentence.spans` | after constituency conversion lands |
| `discourse` | `Sentence.discourse_links` | per-link target placeholder |

## Edge types

| edge_type | meaning | populated by |
|---|---|---|
| `dep` | UD dependency from dependent → head | `Token.dep_head_idx` |
| `agreement` | gender/number/definite axis match | `Morphology.agreement_with` + construction-level relations |
| `clause_member` | token/construction → clause; clause → parent | clause+construction loaders |
| `construction_member` | token → construction (head flag in metadata) | construction-detector pass |
| `semantic_link` | predicate → argument (placeholder for now) | future Arabic PropBank ingestion |
| `discourse_link` | token → discourse target | `DiscourseLink` records |
| `coref` | co-reference (placeholder for now) | future co-ref module |

## Public API

```python
from irab_tashkeel.grammar_graph import (
    build_sentence_graph,            # build from a Sentence
    build_corpus_graphs,             # build from a list
    graph_depth,                     # max BFS depth
    shortest_path,                   # path query with edge-type filter
    constructions_at_token,          # which constructions cover a token
    overlap_constructions,           # tokens with ≥ 2 constructions
    walk_to_governor,                # climb dep edges
    find_construction_clause_membership,
    filter_by_curriculum,            # subset for a curriculum stage
    to_sparse,                       # sparse export (numpy)
    batch_sparse,                    # batch (PyG-compatible)
    bridge_to_schema,                # → schema_v2.GrammarGraph
    write_jsonl, read_jsonl,         # corpus IO
)
```

## Sparse export shape

`to_sparse(g)` returns:

| field | dtype | shape | meaning |
|---|---|---|---|
| `edge_index` | int64 | (2, n_edges) | source / destination indices |
| `edge_type`  | int64 | (n_edges,)    | EDGE_TYPES index |
| `edge_attr`  | float32 | (n_edges, 1) | confidence |
| `node_type`  | int64 | (n_nodes,)    | NODE_TYPES index |
| `node_attr`  | float32 | (n_nodes, k) | per-token confidences (case/role/marker) |

`batch_sparse([g1, g2, ...])` concatenates with the `batch`
sidecar array (PyG-compatible).

`SparseGraph.to_torch()` lazy-imports torch and returns torch
tensors suitable for direct GNN consumption.

## Curriculum-aware filtering

```python
# Stage 1 — pure morph training (drop higher-level nodes)
g_morph = filter_by_curriculum(g, keep_node_types=["token"])

# Stage 4 — nested syntax (no semantic / discourse / coref edges)
g_nested = filter_by_curriculum(
    g, keep_edge_types=["dep", "clause_member", "construction_member"],
)

# Stage 3 — simple constructions (drop ambiguous ones)
g_simple = filter_by_curriculum(g, drop_ambiguous_constructions=True)
```

## Depth metrics

`graph_depth(g, root_type="clause")` performs BFS from matrix-clause
roots (or fallback nodes with no incoming edges) and returns the
max distance reached. Useful for difficulty scoring at curriculum
construction time.

## Bridging to schema_v2

`Sentence.graph` is a *flat* schema_v2 slot that only carries
token-to-token edges. The `SentenceGraph` here is a *richer*
multi-level representation that the schema slot can't hold without
schema migration. Use `bridge_to_schema(g)` to project the rich
graph down to the flat slot when persisting alongside the sentence
record. For full fidelity, write the SentenceGraph as a sidecar
JSONL via `write_jsonl(path, graphs)`.

## Storage layout

```
data_v2/graphs/<source>/all.graph.jsonl   — one SentenceGraph per line
```

Generated by `scripts/data_v2/build_grammar_graphs.py` (forthcoming;
the schema_v2 corpus build does not run the graph engine yet —
keeps the corpus build deterministic and fast).

## Open questions

- Heterogeneous-graph training framework choice: PyG vs DGL vs
  custom sparse-tensor pipeline. PyG has better community / tutorial
  coverage but DGL handles heterogeneous graphs more cleanly;
  pending Step 6 backbone benchmark to decide.
- Edge weight design: for now, `edge_attr` is just confidence.
  Future: add edge-type-specific feature columns (e.g., agreement
  axes one-hot, dep-distance bucket).
- Co-ref edge population: requires Arabic co-ref resolver; defer
  until Step 11.
